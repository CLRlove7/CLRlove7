# 🎯 飞控软件测试 Agent - 任务分解策略

> 本报告详细阐述基于 Supervisor-Agent 架构的多级任务分解与路由调度机制

---

## 📌 核心挑战

在航空飞控软件测试场景中，面临着三大核心挑战：

1. **任务复杂性**：飞控软件涉及多模块耦合、实时性要求高
2. **知识依赖**：测试用例生成需要航空领域专业知识
3. **策略选择**：不同代码路径适合不同的测试生成策略

## 🔄 多级任务分解

### 第一级：功能模块分解

将飞控软件按功能划分为独立测试模块：

| 模块类别 | 示例 | 测试重点 |
|---------|------|---------|
| 飞行控制 | 高度控制、姿态控制 | 实时性、稳定性 |
| 传感器融合 | GPS、惯性导航 | 数据一致性 |
| 通信协议 | 地面站通信、遥测 | 协议合规性 |
| 故障处理 | 传感器失效、链路中断 | 容错恢复 |

### 第二级：测试用例分解

对每个功能模块，按测试目标进一步分解：

```
输入空间划分 → 边界条件识别 → 路径覆盖规划
```

**关键指标**：
- 分支覆盖率 ≥ 95%
- 边界覆盖率 ≥ 90%
- 关键路径覆盖率 100%

### 第三级：策略选择分解

根据代码特征自动选择最优策略：

| 代码特征 | 推荐策略 | 理由 |
|---------|---------|------|
| 含复杂循环/条件 | 符号执行 | 精确路径探索 |
| 含外部输入 | 模糊测试 | 高效缺陷发现 |
| 含业务逻辑 | LLM 生成 | 语义理解优势 |

## 🧠 LLM 路由调度

### 决策流程

```python
# 伪代码：策略选择决策
def select_strategy(code_analysis):
    complexity = analyze_complexity(code_analysis)
    has_external_io = detect_external_io(code_analysis)
    has_business_logic = detect_business_logic(code_analysis)
    
    if complexity > THRESHOLD_HIGH:
        return "symbolic_execution"
    elif has_external_io:
        return "fuzzing"
    elif has_business_logic:
        return "llm_generation"
    else:
        return "hybrid"  # 组合策略
```

### 路由依据

| 维度 | 权重 | 指标 |
|-----|-----|------|
| **圈复杂度** | 0.3 | CC > 15 → 符号执行 |
| **外部依赖** | 0.25 | 含文件/网络/数据库 → 模糊测试 |
| **业务语义** | 0.25 | 含业务规则/校验逻辑 → LLM |
| **历史缺陷** | 0.2 | 类似代码历史问题率 |

## 🔗 与其他模块的协同

### 与 AssertPath-LLM 的协同

任务分解的结果直接作为断言生成的输入：

1. **分解阶段**：识别需要断言的程序点
2. **生成阶段**：基于分解结果生成精确断言
3. **反馈阶段**：断言执行结果反哺任务规划

### 与领域知识库的协同

1. **知识检索**：根据任务类型检索相关测试模式
2. **知识注入**：将领域知识注入 LLM 提示
3. **知识积累**：测试成功后更新知识库
